# 30 ТАЙН СУДЬБЫ — WHATSAPP FINAL

## Что готово
- Адаптивный мистический сайт: 30 вопросов, RU/KY переключатель интерфейса (исходные вопросы и персональные тексты пока на русском), символический портрет, цена 399 сом, имя и WhatsApp вместо email.
- Сервер Python: SQLite, случайный номер заказа, валидация всех 30 ответов, запрет PDF до подтверждения оплаты, защищённая админ-панель `/admin`, PDF по оригинальным 131 вариациям текста, 12 SVG и 144 сочетаниям знаков.
- Ручная отправка: администратор подтверждает платёж, скачивает PDF и вручную прикладывает его к подготовленному сообщению WhatsApp.
- Официальная интеграция WhatsApp Cloud API: **код подключения предусмотрен, но не активирован и не протестирован**. Нужны токен Meta, Phone Number ID и действующее разрешённое окно переписки; за пределами 24 часов нужен утверждённый шаблон Meta. Никаких неофициальных ботов.

## Важно: не загружайте на Netlify весь архив
Netlify публикует только **папку `website`**. Сервер `server/app.py` размещается на отдельном Python-хостинге. Именно отсутствие сервера вызывало ошибку `Unexpected token '<' ... is not valid JSON`. Новая версия показывает понятную ошибку подключения вместо JSON-исключения.

## Локальная проверка на Windows
1. Установите Python 3.11+ с https://www.python.org/downloads/ (галочка **Add python.exe to PATH**).
2. Распакуйте архив, откройте терминал в корне папки проекта.
3. Выполните `py -m pip install -r requirements.txt`.
4. Создайте длинный случайный секрет (не меньше 24 символов) и задайте его в PowerShell: `$env:ORACLE_ADMIN_TOKEN="ВАШ_ДЛИННЫЙ_СЕКРЕТ"`.
5. Задайте номер администратора: `$env:ORACLE_ADMIN_WHATSAPP="996XXXXXXXXX"`.
6. Выполните `py server/app.py`.
7. Откройте `http://127.0.0.1:8080/api/health` для проверки сервера. Чтобы локально проверить клиентский сайт, в `website/config.js` временно установите `window.ORACLE_API_BASE = "http://127.0.0.1:8080"`, но CORS потребует `ORACLE_SITE_ORIGIN` под адрес локального фронтенда. Проще публиковать фронтенд на Netlify и сервер на HTTPS-хостинге.

## Публикация сервера (Render или другой Python-хостинг)
1. Разместите содержимое проекта в приватном репозитории GitHub (без базы заказов и секретов).
2. На Render создайте Web Service из репозитория или используйте `render.yaml`. Услуга с постоянным диском может быть платной; **без постоянного диска SQLite потеряет заказы при перезапуске/пересоздании**.
3. Команда сборки: `pip install -r requirements.txt`, запуска: `python server/app.py`.
4. Переменные: `ORACLE_ADMIN_TOKEN` (секрет от 24 символов), `ORACLE_ADMIN_WHATSAPP` (номер без плюса), `ORACLE_SITE_ORIGIN` (точный URL Netlify, например `https://example.netlify.app`), `ORACLE_DB=/var/data/orders.sqlite3` при подключённом диске.
5. Откройте `https://ВАШ-СЕРВЕР/api/health` и убедитесь, что возвращается JSON с `ok: true`.
6. В файле `website/config.js` укажите `window.ORACLE_API_BASE = "https://ВАШ-СЕРВЕР";` (без `/` в конце). Перезагрузите папку `website` в Netlify.
7. Панель администратора: `https://ВАШ-СЕРВЕР/admin`; секрет вводится вручную, не публикуйте его. Подтверждайте платежи **только после проверки банковской выписки**.
8. Проведите полный тест: 30 ответов → заказ → ручная проверка платежа → PDF → WhatsApp. Не принимайте реальные платежи до тестирования.

## WhatsApp Business Platform API
Для официальной отправки требуются Meta Business Portfolio, WhatsApp Business Account, зарегистрированный номер, Phone Number ID, долгоживущий токен с разрешениями и согласие клиента на сообщения. Установите на сервере:
- `WA_ACCESS_TOKEN` — секрет Meta, не помещать в JS.
- `WA_PHONE_NUMBER_ID` — ID отправляющего номера.
- `WA_API_VERSION` — поддерживаемая версия Graph API (проверьте актуальную в Meta).
- `WA_24H_WINDOW_CONFIRMED=true` — **только когда действительно подтверждено открытое 24-часовое окно после входящего сообщения клиента**.

Администратор может нажать «Отправить через API» в админ-панели. Сервер загружает PDF в официальный endpoint `/media` и отправляет документ через `/messages`. Если окно переписки не открыто, сервер запрещает отправку. Для сообщений вне 24 часов необходимо отдельно реализовать и согласовать approved template и webhook входящих сообщений. API-ответ `messages[0].id` означает приём запроса Meta, **не подтверждение доставки**; для проверки нужны status webhooks.

## Безопасность и юридические требования
- HTTPS, резервные копии SQLite, контроль доступа, ограничение запросов на прокси, логирование без чувствительных данных, регулярные обновления обязательны для коммерческой эксплуатации.
- Не публикуйте `runtime/`, секрет администратора и Meta API token. Админ-панель защищена токеном, но для промышленного сервиса рекомендуется отдельная полноценная авторизация с 2FA.
- Перед приёмом оплаты добавьте публичную оферту, контакты, политику персональных данных с реальными сроками хранения, правила возврата, сведения о продавце и юридическую проверку по законодательству КР.
- Переключатель RU/KY переводит основные элементы интерфейса. Для **полной** кыргызской локализации необходимо отдельно перевести 30 вопросов, 131 вариант предсказаний, политику и PDF. Исходные художественные тексты сохранены на русском, автоматический перевод не выдаётся за готовый кыргызский контент.
- Гадание — художественная интерпретация, не научный прогноз.

## Проверка API
`GET /api/health` — статус сервера.
`POST /api/orders` — имя, phone, answers[30], consent, partner_sign, language.
`GET /api/admin/orders` — Bearer секрет.
`POST /api/admin/confirm/<id>` — Bearer секрет и JSON `{"payment_reference":"BANK-REF-12345"}`.
`GET /api/admin/pdf/<id>` — только оплаченный заказ, Bearer секрет.
`POST /api/admin/send-whatsapp/<id>` — только оплаченный заказ, официальный Meta API, Bearer секрет.

Автоматическая отправка и банковская оплата **не подключены**. Этот архив — рабочая кодовая база для дальнейшего развёртывания, а не подтверждённый готовый коммерческий сервис.
